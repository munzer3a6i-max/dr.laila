# موقع د. دلال العصيمي · Dr. Dalal Al-Osaimy

صفحة واحدة ثنائية اللغة (عربي / English) لأخصائية نفسية للأطفال والمراهقين،
مبنية من تصميم Figma، مع **نظام حجز متصل بـ Cal.com** يكتب المواعيد مباشرة
على تقويمك.

A bilingual (Arabic RTL / English LTR) single-page site built from the Figma
design, with a **Cal.com-backed reservation system** that writes appointments
straight to your calendar.

---

## التشغيل / Running it

```bash
node dev-server.js          # http://localhost:3000
```

`dev-server.js` يقدّم الموقع **و** يشغّل نقاط `/api`، فتختبر تدفّق الحجز الحقيقي
محليًا تمامًا كما سيعمل بعد النشر. بدون `CAL_API_KEY` سيعمل في الوضع المحلي.

It serves the static site **and** runs the `/api` handlers, so the real booking
flow can be tested locally exactly as it behaves in production.

> فتح `index.html` مباشرة بالنقر المزدوج يعمل أيضًا، لكن الحجز سيكون في الوضع
> المحلي لأن نقاط `/api` غير متاحة.

## البنية / Structure

```
index.html                  ← محتوى الصفحة (مفاتيح data-i18n)
assets/css/styles.css       ← التنسيقات + متغيّرات التصميم
assets/js/i18n.js           ← القاموس العربي/الإنجليزي وتبديل اللغة  ← النصوص هنا
assets/js/booking.js        ← واجهة الحجز  ← إعدادات الحجز هنا
assets/js/main.js           ← الهيدر، قائمة الجوال، مبدّل اللغة، التأثيرات
assets/images/              ← صور مؤقتة (انظر assets/images/README.md)

lib/cal.js                  ← عميل Cal.com (خادم فقط — يحمل المفتاح السري)
api/slots.js, api/book.js   ← دوال Vercel
netlify/functions/*.js      ← دوال Netlify (نفس المنطق)
dev-server.js               ← خادم تطوير محلي
.env.example                ← المتغيّرات المطلوبة
```

## 🌐 تبديل اللغة / Language switch

الزر الدائري (32px) في الهيدر يبدّل بين العربية والإنجليزية. يعرض دائمًا اللغة
التي **ستنتقل إليها**: «EN» عندما تكون الواجهة عربية، و«ع» عندما تكون إنجليزية.

- يغيّر `lang` و `dir` على `<html>`، فينعكس التخطيط بالكامل تلقائيًا.
- يحفظ اختيار الزائر في `localStorage` ويستعيده في الزيارة التالية.
- يعمل حتى على النصوص المُولَّدة بالجافاسكربت: أسماء الأشهر، أيام الأسبوع،
  صيغة الوقت (ص/م ↔ AM/PM)، العملة، ورسائل الخطأ.

**لتعديل أي نص** في أي من اللغتين: `assets/js/i18n.js` — كل النصوص في مكان واحد.

الموقع يفتح بالعربية افتراضيًا. لجعله يتبع لغة متصفّح الزائر، غيّر في
`assets/js/i18n.js`:

```js
var DETECT_FROM_BROWSER = false;   // ← true
```

> النصوص الإنجليزية ترجمة مبدئية كتبتُها — راجعها وعدّلها كما تشائين.

## 📅 ربط Cal.com / Connecting Cal.com

هذا ما يجعل الحجوزات تصل تقويمك مباشرة، ويجعل الأوقات المعروضة **حقيقية**
(لا تُعرض المواعيد المحجوزة أصلًا).

### 1. أنشئي حساب Cal.com واربطي تقويمك

<https://cal.com> → **Apps → Google Calendar** (أو Outlook / iCloud).
هذه الخطوة هي التي تجعل الحجز يظهر على تقويمك ويمنع الحجز المزدوج.

### 2. أنشئي نوع موعد (Event Type) لكل نوع جلسة

أربعة أنواع تطابق ما في الموقع:

| نوع الجلسة | المدة |
|---|---|
| جلسة تعريفية | 50 دقيقة |
| جلسة فردية | 60 دقيقة |
| جلسة عائلية | 90 دقيقة |
| جلسة متابعة | 30 دقيقة |

داخل كل نوع، اضبطي **Availability** على ساعات عملك (الأحد–الخميس ٩–١٢،
الجمعة–السبت ٧–١٠ مساءً). **الأوقات المعروضة في الموقع تأتي من هنا**، لا من
الكود.

### 3. اربطي كل نوع جلسة بنوع الموعد المقابل

الأسهل: استخدمي **رابط الحجز العام** لكل نوع موعد:

```
https://cal.com/munzer-3a6i-tygizv/15min
                ^^^^^^^^^^^^^^^^^^ ^^^^^
                اسم المستخدم        الـ slug
```

في `assets/js/booking.js`:

```js
calUsername: 'munzer-3a6i-tygizv',

sessionTypes: [
  { id: 'intro', labelKey: 'type.intro', minutes: 50, price: 100, calEventSlug: '15min' },
  …
]
```

أو بالرقم إن فضّلتِ: افتحي نوع الموعد في Cal.com وخذي الرقم من الرابط
`https://app.cal.com/event-types/1234567` وضعيه في `calEventTypeId`.

> لا اسم المستخدم ولا الـ slug ولا الرقم سرّي — كلها تظهر في روابط الحجز
> العامة.

**مهم:** طالما أن نوع جلسة واحدًا على الأقل مربوط، فإن الأنواع غير المربوطة
تظهر للزائر كـ«غير متاحة للحجز» بدلًا من توليد أوقات وهمية — حتى لا يستلم
أحد تأكيدًا لحجز غير موجود. اربطي الأربعة قبل النشر.

### 4. مفتاح API (قد لا تحتاجينه)

أنواع المواعيد **العامة** تعمل عادةً بدون مفتاح — الربط بالـ slug وحده يكفي
لقراءة الأوقات وإنشاء الحجز. جرّبي أولًا بدون مفتاح.

إن رجع خطأ 401/403، أو كان نوع الموعد مخفيًا أو ضمن فريق، أنشئي مفتاحًا:
Cal.com → **Settings → Developer → API keys → Add**.
المفتاح **سرّي**: لا يوضع في الكود ولا يُرفع إلى Git. يوضع كمتغيّر بيئة:

```
CAL_API_KEY=cal_live_xxxxxxxxxxxx
CAL_TIMEZONE=Asia/Riyadh
```

### 5. انشري الموقع

الملفات جاهزة للمنصّتين — اختاري واحدة:

**Netlify** — `netlify.toml` جاهز. اربطي المستودع، ثم
Site settings → Environment variables → أضيفي `CAL_API_KEY`.

**Vercel** — `vercel.json` جاهز. استوردي المستودع، ثم
Settings → Environment variables → أضيفي `CAL_API_KEY`.

في الحالتين يصبح المسار `/api/slots` و `/api/book` يعمل تلقائيًا.

> **استضافة ثابتة فقط؟** GitHub Pages لا تشغّل دوال خادم، فلن يعمل الربط
> الحقيقي هناك. استخدمي Netlify أو Vercel (كلاهما مجاني لهذا الحجم).

## ماذا يحدث بعد الربط

1. الزائر يختار نوع الجلسة → الموقع يسأل Cal.com عن أوقات ذلك الشهر.
2. الأيام التي لا تحتوي أي وقت متاح تظهر **معطّلة** في التقويم.
3. الأوقات تُعرض **بتوقيت الرياض** دائمًا (مكتوب أسفل القائمة)، مهما كان
   توقيت جهاز الزائر.
4. عند التأكيد يُنشأ الحجز في Cal.com → يظهر على تقويمك، ويصل بريد تأكيد
   للزائر ولك من Cal.com.
5. لو حجز شخص آخر نفس الوقت أثناء التعبئة، يظهر للزائر «هذا الموعد لم يعد
   متاحًا» ويُطلب منه اختيار وقت آخر — ولا يُسجَّل حجز وهمي.

اسم الطفل وعمره، والخدمة المختارة، وسبب الجلسة تُرسل ضمن ملاحظات الحجز فتظهر
في تفاصيل الموعد على تقويمك.

### الوضع المحلي (Local mode)

إذا لم يكن **أي** نوع جلسة مربوطًا بـ Cal.com، أو تعذّر الوصول إلى الخادم،
يعود النموذج إلى توليد الأوقات من `CONFIG.hours` ويعرض شاشة التأكيد **دون
إنشاء حجز حقيقي**، ويطبع تحذيرًا واضحًا في console المتصفّح. هذا لتبقى الصفحة
قابلة للعرض أثناء التطوير، وليس وضعًا صالحًا للإنتاج.

أما إذا كان **بعضها** مربوطًا فقط، فالأنواع غير المربوطة تُغلق تمامًا ولا
يمكن حجزها — بدلًا من إعطاء تأكيد كاذب.

## ⚠️ ملاحظة عن الدفع / A note on payment

**لا يوجد دفع فعلي حاليًا** — الحجز يُنشأ ويُثبَّت على التقويم فقط. لذلك نص
الزر هو «تأكيد الحجز» (وليس «تأكيد الحجز والدفع» كما في التصميم) حتى لا
يتوقّع الزائر أن يُخصم منه مبلغ.

> عنوان الخطوة الرابعة ما زال «التأكيد والدفع» كما في تصميم Figma. إن أردتِ
> إزالة ذكر الدفع منه أيضًا، غيّري `booking.step4` في `assets/js/i18n.js`
> إلى «التأكيد» (و `Confirm` في الإنجليزية).

لتفعيل الدفع الحقيقي: Cal.com → **Apps → Stripe**، اربطي حساب Stripe، ثم فعّلي
السعر داخل كل Event Type. عندها يطالب Cal.com الزائر بالدفع قبل تثبيت الحجز،
ويمكن عندها إعادة كلمة «والدفع» إلى الزر.

## إعدادات أخرى / Other settings

في `assets/js/booking.js`:

```js
timeZone: 'Asia/Riyadh',   // توقيت العيادة (يطابق CAL_TIMEZONE)
minDaysAhead: 0,           // 0 = الحجز اليوم متاح، 1 = من الغد
maxDaysAhead: 90,          // أبعد يوم يمكن الحجز فيه
weekStart: 5,              // أول عمود في التقويم (5 = الجمعة، مطابق للتصميم)
apiBase: '',               // '' = نفس النطاق؛ أو رابط نشر آخر
```

الأسعار والمدد في `sessionTypes` تُستخدم للعرض في الملخّص فقط؛ المدة المعتمدة
فعليًا هي ما في Cal.com.

## ملاحظات على التنفيذ / Implementation notes

**الحركة (Animations).** نظام الحركة كله في قسم `MOTION` داخل
`styles.css`، ويعتمد على `transform`/`opacity` فقط فلا يحدث أي إعادة تخطيط.
المفاتيح:

- `data-enter` على عنصر → أبناؤه يظهرون بالتتابع عند تحميل الصفحة.
- `data-enter-self` → العنصر نفسه يظهر كقطعة واحدة (للعناصر التي بداخلها
  حركة مستمرة خاصة بها).
- `class="reveal"` → يظهر عند الوصول إليه بالتمرير.
- `data-stagger` → أبناء العنصر يظهرون بالتتابع عند الوصول إليه.

الجافاسكربت يحدد **متى** تبدأ الحركة فقط، ويمرّر ترتيب كل عنصر في المتغيّر
`--i`؛ أما الحركة نفسها فكلها CSS. مدد الحركة وانسيابيتها في متغيّرات
`--dur-*` و `--ease-*` أعلى الملف — غيّريها هناك لتتغيّر في كل الموقع.

> الظهور يستخدم `animation` مع `backwards` وليس `transition` إلى
> `transform:none`. السبب: قسم الحركة يأتي متأخرًا في الملف، ولو ثبّت
> `transform` لكان سيتغلّب على كل تأثيرات `:hover` في الصفحة.

تُحترم `prefers-reduced-motion` بالكامل: يظهر كل شيء فورًا في وضعه النهائي،
وتتوقّف الحركات المستمرة تمامًا. وإذا كان الجافاسكربت معطّلًا، تبقى فئة
`no-js` على `<html>` وتُعرض كل العناصر دون حركة.

**الاتجاه (RTL/LTR).** كل قواعد الاتجاه في CSS منطقية لا فيزيائية
(`text-align:start`، `inset-inline-*`، `margin-inline-*`، `flex-start`)، فلا
توجد قاعدة واحدة مكتوبة بـ `left` أو `right`. لذلك ينعكس التخطيط بالكامل
عند تبديل اللغة دون أي CSS خاص بالإنجليزية. أسهم التقويم تنعكس تلقائيًا،
وأسهم لوحة المفاتيح تتبع الاتجاه المرئي.

**الخطوط.** التصميم يستخدم `Thmanyah Sans` وهو غير متاح على Google Fonts.
الصفحة تطلبه أولًا ثم تعود إلى `IBM Plex Sans Arabic` (الخط الثاني في التصميم
نفسه، ويغطي العربية واللاتينية معًا). إن كان لديك ترخيصه، أضيفي `@font-face`
في أعلى `styles.css` وسيُستخدم تلقائيًا.

**الصور.** لم يكن الوصول إلى صور Figma ممكنًا أثناء البناء، فكل الصور في
`assets/images/` مؤقتة بصيغة SVG — التفاصيل في
[`assets/images/README.md`](assets/images/README.md). الشعار وأيقونات البطاقات
والرسوم النباتية مرسومة يدويًا كـ SVG.

**القائمة.** روابط `طريقة العمل` و `الاسئلة الشائعة` و `تواصل معنا` كانت في
تصميم الهيدر بلا أقسام مقابلة، فحُذفت وبقيت الأقسام الموجودة فعلًا.

**بطاقات الخدمات.** التصميم فيه خمس بطاقات، اثنتان منها متطابقتان. البطاقة
الخامسة هنا «استشارات الأطفال والمراهقين» بنص مبدئي — عدّليها كما تشائين.
